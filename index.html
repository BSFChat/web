Run your own server

The server and identity provider ship as OCI images on GHCR (ghcr.io/bsfchat/server, ghcr.io/bsfchat/identity). The reference docker-compose.yml lives in github.com/BSFChat/deploy and brings up the chat server, an OIDC identity provider and a TURN relay for voice. You edit one file, .env; setup.sh generates the rest from it. 

git clone https://github.com/BSFChat/deploy.git /opt/bsfchat
cd /opt/bsfchat
cp .env.example .env
$EDITOR .env        # CHAT_HOST, ID_HOST, TURN_HOST, TURN_EXTERNAL_IP
./setup.sh          # renders config/*.toml and nginx/bsfchat.conf
docker compose up -d

Both HTTP services bind to loopback, so put a reverse proxy in front — setup.sh renders an nginx config for it. The deploy README covers that, TLS, backups and the two settings people get wrong.

Identity is federated on purpose: one account can work across every BSFChat server, so your users don't need a new login per server. The deploy stack runs its own provider at your ID_HOST; any OIDC-compliant provider works, including the shared one at id.bsfchat.com.
